> 面向接手的模型或人员。读完本文即可继续推进、复核或验收，无需回溯此前的对话。

## 1. 这是什么

把 pstack（Cursor 的工程工作流 skill 插件）翻译为中文，使中文使用者能以母语驱动同一套工作流。

翻译不是文学转写，而是**功能性移植**：skill 的每一句话都是给 agent 的执行指令，措辞直接影响 agent 行为。因此准确性优先于流畅度。

## 4. 已修的三个校验器缺陷

`scripts/check-skills-zh.mjs` 是本项目自写的覆盖率校验器。它在使用中暴露了三个错误假设，均已修正。接手者需要知道修正理由，否则可能误以为脚本被削弱了。

### 4.1 只有 `SKILL.md` 需要 frontmatter

- **原假设**：每个 `.md` 都必须有 YAML frontmatter。
- **事实**：上游 23 个 playbook 与全部 `references/` 下的文件都没有 frontmatter，只有 `SKILL.md` 有。frontmatter 的作用是让 Cursor 注册该 skill，附属文档无需注册。
- **修正**：仅当路径以 `SKILL.md` 结尾时检查 frontmatter。
- **影响**：消除了 23 条误报。

### 4.2 链接校验跳过占位符

- **原假设**：所有 markdown 链接都必须解析到真实文件。
- **事实**：`why/references/synthesizer-prompt.md` 里有一条示例链接 `[PR #123](url)`，`url` 是占位符而非路径；上游原文即如此。
- **修正**：跳过 `href === "url"` 与含 `{` 的占位符链接。
- **已做反向验证**：真实失效链接 `./nonexistent-file.md` 仍会被抓到，规则未放宽过度。

### 4.3 statechart 测试语料不纳入翻译

- **原假设**：所有上游 `.md` 都需翻译。
- **事实**：`skills/statechart/scripts/test/corpus/*/report.md` 是测试用的**期望输出快照**，翻译它会改变测试断言的内容。
- **修正**：用 `TEST_CORPUS_FIXTURE` 正则排除该模式，共 33 个文件。
- **同类待办**：`create-verification-skill/references/feature-map-example/` 的 3 个文件性质相同，**建议一并加白名单**。

## 5. 翻译方法论（必须遵守）

### 5.1 三类内容，三种处理

| 类别 | 处理 | 例 |
|---|---|---|
| **代码块** | **逐字保留，绝不翻译** | bash / JSON / YAML / SQL / text 块 |
| **标识符** | 原样保留 | `gh pr merge --squash`、`{{SLACK_CHANNEL_ID}}`、`send_datadog_logs` |
| **说明性散文** | 译为中文 | 标题、段落、列表项 |

### 5.2 术语保留英文

沿用既有习惯（见 `translations/skills-zh/_术语表.md`）：`skill`、`agent`、`subagent`、`workflow`、`playbook`、`prompt`、`PR`、`commit`、`branch`、`worktree`、`rebase`、`CI`、`MCP`、`artifact`、`telemetry`、`symptom`、`finding`、`verdict` 等保留英文。

理由：这些词在中文技术语境中已是通用词，硬译反而增加理解成本；且它们常与代码里的字面量对应，译成中文会割裂对应关系。

### 5.3 新增术语的处理

遇到术语表里没有的词，两种做法：

1. 沿用英文（默认）。
2. 若必须译，**首次出现时用「中文（英文）」标注**，例如「承重行为（load-bearing behavior）」。

### 5.4 句式

- 保留原文的祈使句语气（"Read the diff" 译为「读 diff」，而非「你应该读 diff」）。
- 保留原文的强调结构（加粗的 **Never**、**MUST** 等）。
- 原文刻意用短句的地方不要合并成长句。

## 6. 每篇的验证流程

每译完一篇，至少核对以下各项。全部机械化，不靠肉眼：

| 检查项 | 方法 |
|---|---|
| 标题层级数量一致 | 统计各级标题出现次数 |
| 标题顺序一致 | 提取全部标题文本序列，逐项比对 |
| 列表项数量一致 | 统计有序与无序列表项 |
| **代码块逐字一致** | 提取全部代码块，用 `-ceq` 精确比对 |
| 占位符完整 | 提取 `{...}`、`{{...}}`、`<...>`，比对集合 |
| 行数一致 | 比对非空行数 |
| 无 CRLF | 检查字节 13 |

**代码块逐字比对是最重要的一项**——它是唯一能证明「没把命令改错」的手段。

## 7. 已踩过的坑（接手必读）

### 7.1 `multi-phase-plan.md` 内嵌的骨架必须保持英文

`poteto-mode/playbooks/multi-phase-plan.md` 内嵌了一份 markdown 计划模板。`scripts/check-plan.mjs` 会**硬编码校验英文标识**：

```js
const SUB_BLOCKS = ["Depends on.", "Files.", "Build.", "You see.", "Verify, unit.", ...];
const RULE = "Tests alone are not sufficient verification. ...";
const LANES = /Ten lanes on `[^`<>]+` at the PR head/;
```

若把骨架译成中文，生成的每份计划都会校验失败。**已实测对照验证**：英文骨架 + 填入 model 得到 `0 problems`；本地化 3 个子块名后立即报 `sub-blocks are [...], expected [...]`。

因此该骨架**按字节从原文提取后原样嵌入**，未做任何改动（9284 字节 `-ceq` 完全一致）。

### 7.2 `feature-map.example.md` 的 35 个四级标题

benny 的 feature-map 示例有 35 个 `####` 标题（5 个 feature 乘以 7 个固定段落）。这些是填图模板骨架，顺序错一个就填不了。已逐项验证顺序完全一致。

### 7.3 frontmatter 的 `name` 必须与目录名一致

三个 benny `SKILL.md` 的 `description` 保持英文（agent 靠它发现 skill），`name` 与目录名严格对应。

### 7.4 状态字符串是匹配用的枚举

`reproduce-and-fix-issues/SKILL.md` 里的 `Reproducing`、`Could not reproduce`、`Blocked` 等状态值，以及 `reflect/references/synthesizer.md` 里 9 个拒绝原因（`durability` 到 `already-covered`），都是**下游按字符串精确匹配的枚举**，译成中文会导致匹配失败。

### 7.5 `slack.md` 上游本身有编号缺陷

`why/references/sources/slack.md` 的编号是 1、3、4（缺 2）。这是**上游原文的笔误**。译文原样保留，以便与上游保持一致、便于 diff 对照。**不要「修好」它。**

## 9. 提交约定

- 每完成一组独立单元提交一次，commit message 用 Conventional Commits。
- 只 `git add` 明确路径，绝不用 `-A`。
- 译文统一用 **UTF-8 无 BOM、LF 换行**。PowerShell 下用 `[IO.File]::WriteAllText` 配 `UTF8Encoding($false)`，避免 shell 重定向产生 BOM。
