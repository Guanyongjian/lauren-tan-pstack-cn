# pstack 中文翻译 — 测试与验收文档

> 供**独立验收方**使用。本文只描述「如何验证」，不描述「如何实现」。验收方无需阅读交接文档即可独立执行。
>
> 验收目标是**证伪**，不是确认。请主动尝试找出问题，而不是走一遍流程确认它没问题。

## 0. 验收前置

### 0.1 环境

需要：Node.js 18+、git、PowerShell（Windows）或 bash。

### 0.2 代码位置

```
<repo>/
  upstream/cursor-plugins/pstack/   # 上游英文原文（基准，只读）
  translations/skills-zh/           # 中文译文（受验对象）
  scripts/check-skills-zh.mjs       # 覆盖率校验器
  docs/翻译/                        # 本目录
```

### 0.3 自动化脚本

验收所需的机械比对脚本已备好，见附录 A。直接运行：

```powershell
pwsh docs/翻译/verify.ps1
```

它会输出 PASS/FAIL 汇总。**但不要只信这个脚本**——第 3 节的手工抽查是必须的，脚本无法判断语义正确性。

---

## 1. 验收等级

| 等级 | 范围 | 适用 |
|---|---|---|
| **L1 结构完整性** | 文件齐全、标题层级、列表数量、行数 | 必须全过 |
| **L2 字面量保真** | 代码块逐字、命令、占位符、枚举值 | 必须全过 |
| **L3 语义正确性** | 译文是否准确传达原意 | 抽样验证 |
| **L4 可用性** | 译文能否实际驱动 agent | 建议验证 |

**任一项 L1 或 L2 失败 = 验收不通过。**

## 2. L1 / L2 自动化验收

### 2.1 运行覆盖率校验器

```bash
node scripts/check-skills-zh.mjs
```

**期望输出**（截至交接时刻）：

```
upstream: 124 files (33 test-corpus fixtures skipped), translations: 108 files
16 problems
```

**判定标准**：

- ✅ `upstream` 行的数字必须与本文档一致（124 / 33 / 108）。
- ✅ `problems` 必须**恰好 16 条**，且**全部**为 `missing translation`。
- ❌ 若出现 `link ... resolves to nothing` → **不通过**（有失效链接）。
- ❌ 若出现 `missing or malformed frontmatter` → **不通过**。
- ❌ 若出现 `translation has no upstream source` → **不通过**（有孤儿译文）。
- ❌ 若 `problems` 数量不等于 16 → 需查明原因（可能有人新增了译文，属正常进展，但需核对）。

**自行确认 16 条的内容**：

```bash
node scripts/check-skills-zh.mjs 2>&1 | grep 'missing translation'
```

应与交接文档第 3 节的「未完成」表格**完全对应**。逐条核对，任何一条不属于该表 → 记为问题。

### 2.2 代码块逐字比对（关键项）

这是**最重要的验收项**。译文里任何一个代码块被改动，都可能导致 agent 执行错误命令。

```powershell
pwsh docs/翻译/verify.ps1 -Check CodeBlocks
```

脚本对每个文件提取全部围栏代码块（包括缩进代码块），用 `-ceq` 逐字节比对。

**判定**：全部必须 `identical=True`。**不允许任何例外。**

### 2.3 占位符完整性

```powershell
pwsh docs/翻译/verify.ps1 -Check Placeholders
```

比对三类占位符的集合：

- 单花括号 `{QUESTION}`、`{FILES_WITH_LINE_RANGES}` 等
- 双花括号 `{{SLACK_CHANNEL_ID}}` 等
- 尖括号 `<channel>`、`<repo>` 等

**判定**：译文的占位符集合必须是上游的**超集或等集**。缺失任何一个 → 不通过。

> 注意：尖括号占位符常用于散文里作示例（如「用 `<filename>` 替换」），译文可能引入原文没有的，这属于正常。但**原文有的绝不能少**。

### 2.4 声明的枚举值

以下内容必须与上游逐字一致，它们**不是散文，是匹配用的字符串**：

| 文件 | 枚举 |
|---|---|
| `automations/benny/templates/triage-automation-prompt.md` | `[benny:bug]`、`[benny:performance]`、`[benny:other]` |
| `automations/benny/skills/reproduce-and-fix-issues/SKILL.md` | `Reproducing`、`Could not reproduce`、`Blocked`、`Reproduced`、`Verifying existing fix`、`Attempting bounded fix`、`Draft pull request opened`、`Fix did not land` |
| `automations/benny/skills/triage-issue-reports/SKILL.md` | 同上 marker 三值 |
| `reflect/references/synthesizer.md` | `durability`、`specificity`、`existing-skill-first`、`convergence`、`decision-changing`、`structural`、`duplicate`、`skill-not-used`、`already-covered` |
| `why/references/epistemics.md` | `Direct`、`Supported`、`Inferred`、`Speculative`、`Unknown` |

```powershell
pwsh docs/翻译/verify.ps1 -Check Enums
```

### 2.5 编码

```powershell
pwsh docs/翻译/verify.ps1 -Check Encoding
```

- 必须是 **UTF-8 无 BOM**
- 必须 **无 CRLF**（不能含字节 `0x0D`）

**判定**：任何一个文件含 BOM 或 CR → 不通过。

## 3. L3 语义正确性（必须抽样，不能省略）

自动化只能证明「结构没坏」，证明不了「意思对」。**请自行抽样。**

### 3.1 抽样建议

随机抽 **不少于 8 篇**，覆盖以下类别：

| 类别 | 建议文件 | 为什么抽它 |
|---|---|---|
| 核心工作流 | `poteto-mode/playbooks/autonomous-run.md` | 整个模式的入口，语义错则全错 |
| 最长最复杂 | `automations/benny/skills/reproduce-and-fix-issues/SKILL.md` | 15 个编号章节，最易出错 |
| 含内嵌骨架 | `poteto-mode/playbooks/multi-phase-plan.md` | 骨架须为英文，见 3.3 |
| 证据体系 | `why/references/epistemics.md` | 置信度分级，措辞敏感 |
| 安全边界 | `automations/benny/skills/triage-issue-reports/SKILL.md` | 含硬性安全规则 |
| 审查模板 | `reflect/references/divergent-reviewer.md` | prompt 模板，语气影响输出 |
| 任意 playbook | 自选一篇 | — |
| 任意 principle | 自选一篇 | — |

### 3.2 语义检查清单

逐段对照原文，问以下问题：

- [ ] **有无漏译？** 原文的某个 bullet / 句子在译文里是否整个消失？
- [ ] **有无增译？** 译文是否加了原文没有的限制、放宽或建议？
- [ ] **有无反义？** 尤其注意否定词：`never` / `do not` / `only` / `unless` / `must not` 是否译对？**这是最危险的错误类型。**
- [ ] **条件是否完整？** `unless`、`only when`、`if...otherwise` 的条件从句是否都在？
- [ ] **祈使语气是否保留？** 原文是命令，译文不应变成建议。
- [ ] **强调是否保留？** 粗体的 **Never** / **MUST** 是否仍是粗体且语气同样强硬？

### 3.3 专项：内嵌骨架必须为英文

检查 `poteto-mode/playbooks/multi-phase-plan.md`：

```powershell
pwsh docs/翻译/verify.ps1 -Check Skeleton
```

该文件内嵌一份 markdown 计划骨架。上游校验器 `check-plan.mjs` **硬编码校验英文标识**（`## How to read this`、`Verify, live.`、`Lane N.`、`Pass when` 等）。

**判定**：骨架块必须与上游**逐字节完全一致**。若发现骨架被译成中文 → **不通过**，因为生成的每份计划都会校验失败。

**可选：端到端验证。** 把骨架抽出成一份计划文件，填入 model 后跑上游校验器：

```powershell
pwsh docs/翻译/verify.ps1 -Check SkeletonE2E
```

期望 `0 problems`。

### 3.4 专项：上游缺陷是否被「修好」

`why/references/sources/slack.md` 的编号应为 **1、3、4**（缺 2）。

**判定**：若译文显示 1、2、3、4 → **记为问题**（说明译者擅自改了上游，破坏 diff 可比性）。

### 3.5 专项：frontmatter 处理

检查三个 benny `SKILL.md` 的 frontmatter：

```powershell
pwsh docs/翻译/verify.ps1 -Check Frontmatter
```

**判定**：

- `name` 必须与所在目录名**完全一致**（如目录 `setup-benny` → `name: setup-benny`）。
- `description` 应为**英文**（agent 靠它发现 skill，译成中文可能影响触发）。
- `disable-model-invocation` 等字段原样保留。

## 4. L4 可用性（建议）

若条件允许，实际驱动一次 agent 用译文工作：

1. 在 Cursor（或兼容环境）中加载 `translations/skills-zh/` 下的 skill。
2. 触发一个简单工作流，例如让 agent 做 `/ketchup`（项目近况汇报）。
3. 观察：agent 是否理解指令？是否执行了预期动作？有无因译文歧义导致的错误？

**典型失败信号**：

- agent 询问本不该问的问题（说明某个 `never-block-on-the-human` 之类的前置条件被译丢了）
- agent 跳过本应执行的验证步骤（说明某个 `MUST` 被弱化）
- agent 引用了不存在的命令（说明代码块或标识符被改动）

## 5. 判决

### 5.1 通过条件

**全部满足**才算通过：

- [ ] 2.1 覆盖率校验器输出与期望一致，且 16 条问题全部为 `missing translation`
- [ ] 2.2 所有代码块逐字一致
- [ ] 2.3 占位符无缺失
- [ ] 2.4 声明的枚举值全部逐字一致
- [ ] 2.5 无 BOM、无 CRLF
- [ ] 3.3 内嵌骨架与上游逐字节一致
- [ ] 3.4 上游缺陷（slack 编号）未被擅自修好
- [ ] 3.5 frontmatter 正确
- [ ] 3.2 抽样 8 篇以上，未发现漏译、增译、反义、条件缺失

### 5.2 不通过处理

发现问题的记录格式：

```markdown
## 问题 N

- 文件：<相对路径>
- 位置：<行号或章节名>
- 类型：漏译 / 增译 / 反义 / 条件缺失 / 代码块改动 / 占位符丢失 / 其他
- 原文：<英文原句>
- 译文：<当前中文>
- 影响：<会导致 agent 怎样错误行为>
- 建议：<应如何修改>
```

**「代码块被改动」与「反义错误」优先级最高**，因为它们会让 agent 执行错误命令或做出相反行为。

## 6. 已知的、不算问题的情况

验收方可能遇到以下情形，**它们是设计如此，不要判为缺陷**：

| 情形 | 说明 |
|---|---|
| 术语保留英文（`skill`、`agent`、`commit` 等） | 项目约定，见交接文档 5.2 |
| `{{...}}`、`<...>` 等占位符未译 | 是模板注入点，必须保留 |
| 译文比原文短很多（字节数约为 1/3） | 中文信息密度高于英文，属正常 |
| `slack.md` 编号缺 2 | 上游缺陷，刻意保留，见 3.4 |
| `synthesizer-prompt.md` 里 `[PR #123](url)` 链接失效 | 示例占位符，非真实链接 |
| 部分文件无 frontmatter | 只有 `SKILL.md` 需要，见交接文档 4.1 |
| 16 条 `missing translation` | 尚未完成的批次，见交接文档第 3 节 |
| `create-verification-skill/.../feature-map-example/` 未译 | 示例产物，是否译待决定 |
