# 修根因

调试时，要修**故障本身**，而不是修故障显形的那个位置。症状是错误状态变得可见的地方；根因则是系统第一次做了不该做的事、或第一次没有处理它本该处理的状态的地方。

**Why:** 只修症状会掩盖证据，并让故障继续在其他地方冒头。每做一次，系统就更难推理——因为代码从此背着一个谁也没点名的 bug 的临时补丁。

**Pattern:**

- 先复现。
- 每一步都问「为什么」，直到答案落到某个具体的错误决策上，而不是上一个决策的后果。
- 卡住就加观测。读真实的错误和真实的状态，不要猜。
- 判断触发症状的那个状态是否合法。如果系统**可能**处于该状态，那么在这个状态上崩掉的代码就是根因，就地处理该状态才是修复。如果该状态本就不该存在，那么在崩溃点加检查只会把 bug 藏起来——去找**产生**该状态的东西。守卫、重试、吞掉异常、截断取值、丢弃状态，都是常见的藏 bug 手法。
- 若故障只在重启后出现，优先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。
- 找**模式**，不只找实例。把同一类故障的所有位置都找出来，一并修掉。
- 若一个临时补丁需要一整段注释才能自圆其说，那说明代码错了。修代码，不要修注释。
- 若关键事实是深挖才发现的，就提出那个便宜的、常开的信号，让它在第一眼就能暴露出来。
