# Outcome-Oriented Execution（结果导向执行）

优化朝向预期的、可验证的终态，而不是维持平滑的中间状态。

**Why:** 让每个中间步骤都完全稳定，往往会制造出临时兼容代码，而这些代码会变成长期债务。向目标架构收敛，并在明确的验证边界上证明正确性。

**Core rule:**

- 终态完整性优先于过渡期稳定性
- 中间状态被破坏是可以接受的，前提是它有计划、有范围、可回退

**Guardrails:**

- 用于有明确阶段边界的计划性重写和迁移
- 声明哪些地方允许暂时的破坏
- 迁移期间，对正在改动的区域保留高信号检查
- 计划完成时要求完整的静态与运行时验证
