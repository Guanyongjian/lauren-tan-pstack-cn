# Make Operations Idempotent（让操作幂等）

把操作设计成：无论跑多少次、上次停在哪里，都能收敛到正确状态。每个会改状态的操作都应当回答：「如果它跑两遍会怎样？如果上次跑到一半崩了会怎样？」

**Why:** 命令、生命周期操作和处理循环所处的环境里，崩溃、重启、重试都是常态。如果残留的部分状态会改变下一次运行的结果，那么每次重启都会变成一次排障。

**The idea:** 让每一步都从「当前存在的状态」推导出来，而不是从「上一次运行打算做什么」推导。读当前状态，与目标比较，只应用差异。这样写出来的步骤可以安全重复，因为重复时会发现已经没有事情可做。

运行留下的任何东西——lock、临时文件、写了一半的记录、已被 claim 的 job——都必须能被下一次运行识别为 stale。判断 stale 要依据「无论上次停在哪里都仍然成立」的证据，而不只是常见情况下的证据。一个下一次运行无法判读的 marker，会把每次崩溃都变成人工清理。例如：写入临时路径再 rename 到位，或按内容而非创建顺序比较 artifact。

**The test:**

1. 连续跑两遍会怎样？
2. 如果上一次运行在每一个可能的时点崩溃，会怎样？
3. 重新执行是否收敛到同一个终态？

如果任一答案是「取决于留下了什么状态」，这个操作就需要一个 reconcile 步骤。
