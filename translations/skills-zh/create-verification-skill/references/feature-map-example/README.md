# Notes 验证地图

本目录是验证 Notes 用户可见行为的受维护来源。驱动应用前先阅读索引，再使用对应的功能文件作为操作方案。

## 基线前置条件

- 使用一次性数据目录，在 `http://127.0.0.1:4173` 启动 Notes。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，让并发运行不共享状态。
- 预置标题为 `Quarterly plan` 和 `Grocery list` 的笔记。
- 将 `control-notes` 和 `notes` CLI 放入 `PATH`。
- 运行 `control-notes doctor`，要求 URL、数据目录和构建修订版均符合预期。
- 绝不驱动不是由本次验证运行启动的实例。

## 驱动约定

- 除非前置条件另有说明，每个操作方案都从基线状态开始。
- 优先使用 ARIA 角色和可访问名称，而不是 CSS 选择器或 DOM 位置。
- 每条命令都按字面执行，保留引号中的名称和参数标志不变。
- 通过 `control-notes browser` 执行浏览器操作。
- 通过 `control-notes cli -- <command>` 执行终端操作。
- 修改数据后恢复预置数据。清理时不要删除证据产物。

## 证据与跳过报告

- 采集用户动作及其结果状态，而不只是最终画面。
- UI 证据包括 ARIA 快照和能看到应用身份的截图。
- CLI 证据包括命令、标准输出、标准错误和退出码。
- 数据修改的证据包括从第二个只读视图看到已存储的值。
- 每份证据都记录功能 ID 和使用的入口。
- 路径不可达时，报告尝试过的命令和未满足的前置条件。
- 不得把通过另一条路径验证过的内容报告为已验证某个被跳过的入口。

## 功能条目契约

每个功能文件以 H1 标题开头，接一段对用户可见行为的描述。随后严格按以下顺序使用四个 H2 小节。

1. `Sub-features` 列出简短 ID，每项行为一行。
2. `How to get to it (user POV)` 列出所有用户入口。
3. `Driving it with <harness>` 以 `Preconditions:` 开头，使用带标签的项目符号，把每个用户动作与确切命令和可观察结果对应起来。
4. `Gotchas` 列出可能浪费验证运行或使证据失效的陷阱。

地图中不写实现细节。只点名用户路径、稳定句柄、必需状态、命令和可观察证据。

## 功能

- [创建笔记](./create-note.md) 覆盖浏览器和 CLI 创建、取消、持久化及清理。
- [搜索笔记](./search.md) 覆盖工具栏、键盘和 CLI 搜索，以及匹配、空结果和清除状态。
